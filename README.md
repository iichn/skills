# ai-workflow

Переносимый набор шаблонов для работы с несколькими ИИ-моделями: Lead (человек) → Bridge → Routine / Executor.

## Содержимое
| Путь | Назначение |
|---|---|
| `ARCHITECTURE.md` | Полное описание схемы: роли, цикл задачи, маршрутизация, контракты, приёмка, отказоустойчивость |
| `roles/01-lead-human.md` | Чек-листы для лида |
| `roles/02-claude-bridge.md` | Инструкция для Bridge (планирование, ТЗ, ревью) |
| `roles/03-gemini-routine.md` | Инструкция для Routine (рутина в чате) |
| `roles/04-agent-executor.md` | Инструкция для агента в IDE (копируется в проект) |
| `roles/05-fallback-any-model.md` | Универсальная инструкция, если доступна одна модель |
| `skeleton/` | Файлы, которые копируются в проект: PLAN, DECISIONS, ACCEPTANCE, шаблон ТЗ, prompt-файлы |
| `bootstrap.sh` | Раскладывает скелет и инструкции агента по проекту |

## Старт нового проекта
```bash
./bootstrap.sh /путь/к/проекту
```
Затем:
1. Заполнить `docs/PLAN.md` (цель, стек).
2. Заполниьб блок «Проект» в `AGENTS.md` и `.github/copilot-instructions.md` (структура, команды сборки и тестов).
3. Вставить `roles/02-claude-bridge.md` в инструкции проекта Bridge.
4. Вставить `roles/03-gemini-routine.md` в Gem / сохранённую инструкцию Routine.
5. Отправить Bridge цель, получить план, утвердить, выдать задачи.

## Если модели недоступны
Откройте `roles/05-fallback-any-model.md`, вставьте в чат любой модели, укажите роль и ТЗ. Контекст проекта берётся из `docs/`, а не из памяти чата.

## Правила поддержки
- Роли правятся только в `roles/`. Копии в проектах обновляются повторным запуском `bootstrap.sh` в чистую папку и переносом изменений.
- Повторяющаяся правка от тебя на приёмке = новая строка в инструкции соответствующей роли.

# Lead (человек): рабочие чек-листы

Роль: цели, приоритеты, приёмка. Не пишешь рутинный код и не пишешь ТЗ с нуля.

## Перед началом проекта
- [ ] `bootstrap.sh` выполнен, скелет в проекте
- [ ] Заполнены docs/VISION.md и docs/SCOPE.md
- [ ] В `docs/PLAN.md` указаны цель, стек, ограничения
- [ ] В `AGENTS.md` заполнен блок «Проект» (структура, команды сборки и тестов)
- [ ] Инструкции ролей вставлены в Bridge и Routine

## Постановка задачи Bridge
Пиши коротко: цель, ограничения, срок (если есть). Не описывай реализацию, это работа Bridge.
Если Bridge задаёт вопросы, отвечай по пунктам.

## Утверждение плана
- [ ] Каждая задача имеет критерий готовности
- [ ] Нет задач размера L
- [ ] Для каждой указан маршрут (Routine / Executor)
- [ ] Порядок учитывает зависимости

## Приёмка (порядок строгий)
1. [ ] Сборка, типы, линтер, тесты прошли (запускаешь ты)
2. [ ] В диффе нет файлов вне ТЗ
3. [ ] Нет новых зависимостей, переименований, форматирования «заодно»
4. [ ] Критерии «Готово, когда» выполнены
5. [ ] Критичное место (безопасность, данные, деньги, публичный API, миграция)? Отправь дифф Bridge на ревью
6. [ ] Решение: коммит / правка ТЗ и возврат / отклонить

## Приёмка релиза

см docs/ACCEPTANCE.md

## Возврат задачи
Не «переделай», а правка ТЗ: что именно не так, какой критерий нарушен.

## Ретроспектива (в конце каждого релиза)
- Какие правки повторялись? Добавь строку в инструкцию соответствующей роли.
- Какие задачи ушли в откат и почему? Исправь шаблон ТЗ или правила маршрутизации.
